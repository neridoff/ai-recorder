# AI Recorder: этапы E1 (каркас и захват), E2 (выравнивание и дрейф), E3 (расшифровка), E4 (разметка говорящих), E5 (сжатие и срок хранения аудио), E5.1 (сроки, настройки, записи без результата), E5.2 (установка для коллег, проверка обновлений)

[![CI](https://github.com/neridoff/ai-recorder/actions/workflows/ci.yml/badge.svg)](https://github.com/neridoff/ai-recorder/actions/workflows/ci.yml)

Приложение в меню-баре записывает системный звук (ScreenCaptureKit) и микрофон (AVAudioEngine) в две отдельные дорожки. Для каждой дорожки фиксируется время первого сэмпла в host time. При сбое записанное сохраняется.
CLI `mix-session` сводит дорожки в `mixed.m4a` с выравниванием по времени первого сэмпла и замеряет дрейф по anchors.
Запись можно ставить на паузу. После «Остановить запись» приложение само расшифровывает обе дорожки через whisper.cpp без сети, размечает говорящих через sherpa-onnx и пишет `transcript.json` и читабельный `transcript.md`, по завершении приходит уведомление macOS. То же делает CLI `transcribe-session`.
Документы проекта (план, требования, ADR) в репозиторий не входят; ссылки вида FR-05, ADR-004 указывают на них.
Требования: FR-01, FR-02, FR-03, FR-04, FR-05, FR-14, FR-15, FR-16, NFR-01, NFR-02, NFR-03 (план). Решения E2: ADR-003, E3 и E4: ADR-004 (решения 11–22, 23–32 и E4.1: 33–42).

## Установка

Для тех, кто просто хочет пользоваться приложением. Приложение собирается из исходников на вашем Mac, поэтому macOS (Gatekeeper) не блокирует его запуск, а подписи разработчика не нужно.

**Требования:** Mac на Apple Silicon (M1 или новее), macOS 13.3 или новее, около 2 ГБ свободного места, интернет на время установки. Полный Xcode не нужен, хватит инструментов командной строки: установщик предложит их сам.

**Перед записью встречи** предупредите участников и получите их согласие: запись разговора без согласия может нарушать закон и правила вашей компании. Приложение записывает, расшифровывает и размечает говорящих только на вашем Mac, без сети. Если вы хотите получить саммари встречи, текст из `transcript.md` вы передаёте внешнему сервису (например, чат-боту) сами, вручную: приложение никуда его не отправляет. Проверьте, можно ли передавать этот текст по правилам вашей компании.

**Установка — две строки в Терминале** (репозиторий [github.com/neridoff/ai-recorder](https://github.com/neridoff/ai-recorder)):

```bash
git clone https://github.com/neridoff/ai-recorder.git "$HOME/Library/Application Support/AI Recorder/source"
cd "$HOME/Library/Application Support/AI Recorder/source" && ./install.sh
```

Исходники лежат в `~/Library/Application Support/AI Recorder/source`, рядом с моделями, а не в «Документах»: там возможна синхронизация iCloud и отдельные запросы macOS на доступ к папке.

**Что будет на экране.** Установщик идёт по пяти шагам и для каждого пишет статус: «готово» (сделано сейчас), «есть» (уже было, пропущено), «ошибка».

```
[1/5] Инструменты разработчика ................... есть
[2/5] Библиотека sherpa-onnx (около 9 МБ) ........ готово
[3/5] Модели (около 610 МБ) ...................... готово
[4/5] Сборка приложения .......................... готово
[5/5] Установка в /Applications .................. готово
```

Во время загрузки видна полоска curl, во время сборки одна строка текущего прогресса. Полный журнал: `~/Library/Logs/AI Recorder/install.log`; при ошибке установщик покажет его последние 20 строк и номер шага. В конце в Терминале «Установка завершена», путь к приложению и три следующих шага, приходит уведомление «AI Recorder установлен». Уведомление приходит от имени Терминала (или Script Editor), а не со значком AI Recorder: так macOS показывает уведомления скриптов, это нормально. Первая установка занимает около 10–15 минут, в основном загрузка моделей и сборка.

**Куда ставится.** В `/Applications`, а если у вашей учётной записи нет прав на запись туда, в `~/Applications` (папка «Программы» в вашей домашней папке). Если приложение уже стоит в `~/Applications`, обновление ставится туда же. Модели лежат в `~/Library/Application Support/AI Recorder/Models`, записи в `~/Documents/AI Recorder`.

**Что сделать руками:**
1. Если инструментов разработчика нет, установщик откроет окно их установки и остановится. Подтвердите установку в окне, дождитесь её конца и запустите `./install.sh` снова.
2. Запись экрана и системного звука. Установщик сам откроет нужный раздел Системных настроек: включите там AI Recorder и перезапустите приложение (значок волны в строке меню → «Выйти», затем откройте AI Recorder из «Программ»).
3. Микрофон. macOS спросит разрешение при первой записи: нажмите «Разрешить».

**Обновление.** В меню приложения есть пункт «Проверить обновления…» (см. ниже). Обновиться можно и без него, в Терминале:

```bash
cd "$HOME/Library/Application Support/AI Recorder/source" && git pull && ./install.sh
```

Установщик закроет старую версию (если идёт запись, он остановится и попросит её завершить), пересоберёт приложение и заменит его. **После пересборки разрешения macOS сбрасываются:** подпись у приложения своя для каждой сборки (ad-hoc), и macOS считает новую сборку другим приложением. Включите запись экрана заново в открывшихся настройках. Если переключатель AI Recorder там уже включён, а запись не стартует, удалите строку AI Recorder кнопкой «−» и добавьте приложение снова. Если ничего не изменилось, повторный запуск `./install.sh` ничего не перекачивает и не пересобирает.

**Проверка обновлений (FR-27, ADR-007).** Пункт меню «Проверить обновления…» делает один запрос к GitHub (`api.github.com`) только когда вы его нажимаете. Других запросов в сеть приложение не делает: ни при запуске, ни по расписанию, ни во время записи и обработки (тогда пункт неактивен). В запросе нет ваших данных (ни аудио, ни текста, ни названий записей), только версия приложения в заголовке User-Agent; GitHub при этом видит IP-адрес вашего Mac. Если вышла новая версия, откроется окно с кнопкой «Скопировать команду»: вставьте её в Терминал и нажмите Enter. Приложение само ничего не скачивает и не устанавливает. Пока вы не обновились, в меню виден пункт «Доступно обновление X.Y.Z».

**Удаление.**
1. Выйдите из приложения (значок волны → «Выйти») и перенесите `AI Recorder` из `/Applications` (или `~/Applications`) в Корзину.
2. При желании удалите папку `~/Library/Application Support/AI Recorder` (исходники и модели, около 1 ГБ) и журнал `~/Library/Logs/AI Recorder`.
3. Записи в `~/Documents/AI Recorder` никто не удаляет автоматически: решите сами, нужны ли они.
4. Разрешения можно убрать в Системных настройках → Конфиденциальность и безопасность.

**Модели и библиотеки.** Всё скачивается с проверкой SHA-256 (суммы закреплены в `scripts/` и `Package.swift`). Лицензии сверены 03.11.2026 по карточкам моделей и репозиториям:

## Сборка и запуск

Для разработчиков. Обычная установка — раздел «Установка» выше.

```bash
cd app
./scripts/fetch-sherpa-onnx.sh     # один раз до первой сборки: dylib sherpa-onnx, 9 МБ архив (нужна сеть)
./scripts/fetch-models.sh          # один раз: модели расшифровки и разметки, 610 МБ (нужна сеть)
swift build && swift test          # 177 тестов RecorderCore (и замер ArchivePerf, по умолчанию пропускается) и 8 тестов приложения
./scripts/build-app.sh             # build/AIRecorder.app и CLI verify-session, mix-session, transcribe-session, diarize-session
open build/AIRecorder.app
```

Первая `swift build` скачивает `whisper.xcframework` (сборка b5454, около 66 МБ, checksum закреплён в `Package.swift`). `fetch-sherpa-onnx.sh` кладёт в `Vendor/sherpa-onnx/` готовые `libsherpa-onnx-c-api.dylib` и `libonnxruntime.dylib` релиза v1.13.8 (33 МБ) и заголовок C API, без них `swift build` не слинкуется; `build-app.sh` вызывает его сам. Модели лежат в `~/Library/Application Support/AI Recorder/Models/`: `ggml-large-v3-turbo-q5_0.bin` (Whisper), `ggml-silero-v6.2.0.bin` (детектор речи), `sherpa-onnx-pyannote-segmentation-3-0.onnx` (6 МБ, сегментация говорящих) и `3dspeaker_speech_campplus_sv_zh_en_16k-common_advanced.onnx` (28 МБ, голос). Скрипты сверяют SHA-256 и не перекачивают готовые файлы. Сеть нужна только им и первой сборке, запись, расшифровка и разметка работают без сети.

Иконки (E4.2, дизайн): `build-app.sh` собирает `AppIcon.icns` из `Resources/Icons/AppIcon-1024.png` (sips и iconutil, 16–512 pt в @1x и @2x; в репозитории только PNG) и копирует глифы `Resources/Icons/MenuBar` в `AIRecorder.app/Contents/Resources/MenuBar`. Приложение берёт их через `Bundle.main` (PDF, 18×18 pt). С E5.1 тот же PNG собирается ещё и в каталог ресурсов `Assets.car` (`actool` из Xcode, в `Info.plist` есть `CFBundleIconName`): Если в уведомлении всё же пустая плашка, это старая запись Центра уведомлений: способ сброса в чек-листе E5.1. В конце `build-app.sh` регистрирует `.app` в Launch Services (`lsregister -f`). Без `.app` (`swift run`) глифов нет, в меню-баре прежние SF Symbols. Правки иконок делаются в Figma, файлы экспортируются заново; код геометрию не рисует.

В меню-баре появится значок волны. Меню:
- «Начать запись» / «Остановить запись», клавиша ⌘R;
- во время записи «Пауза» / «Продолжить запись», клавиша ⌘P;
- время записи и текущий сдвиг mic − system;
- переключатель «Несколько голосов в комнате»: если рядом с вами в комнате говорят другие люди, `mic` тоже размечается по говорящим (до, во время или после записи, действует на текущую или последнюю запись);
- переключатель «Не удалять аудио этой записи» (E5.1, FR-13): действует на текущую запись (пишется в `session.json` при остановке) или, после остановки, на последнюю; защищает и исходные, и сжатые дорожки от удаления по сроку;
- после «Остановить запись» обработка начинается сама (ADR-004 решение 34; «Пауза» её не запускает; выключается в настройках): «Расшифровка, N%», затем «Разметка, N%» и «Отменить расшифровку», в конце «Готово: реплик N, собеседников M» с «Показать расшифровку в Finder» (выделяет `transcript.md`) или «Ошибка расшифровки: …». Если речи в записи нет, «Расшифровка пустая, аудио сохранено». Время записи и проценты обновляются и при открытом меню. Кнопок запуска расшифровки в этом блоке нет, ⌘T убрано (E5.1): повтор только из списка ниже;
- «Записи без результата (N)» (E5.1, ADR-006 решение 8), виден только если такие записи есть: записи с исходными дорожками на диске и без успешного результата. Строка: «ДД.ММ ЧЧ:ММ, N мин, причина, удалится ДД.ММ» (или «хранится», если включено «Не удалять аудио», срок «не удалять» или запись сделана до перехода на E5.1). Причины: ошибка расшифровки, ошибка разметки, отменена, не запускалась, восстановлена после сбоя, пустой результат. У каждой строки подменю: «Повторить расшифровку» (в общую очередь; после ошибки расшифровки продолжает с готовых чанков, при пустом результате начинает заново), «Показать в Finder», «Не удалять аудио», «Удалить…» (после подтверждения вся папка записи уходит в Корзину macOS, вернуть можно оттуда; для записи в очереди или в обработке неактивно). Новые сверху, не больше 10, дальше «Ещё N… открыть папку записей». Под списком «Повторить все (N)», от старых к новым. Запись в очереди или в обработке помечена «в очереди» / «в обработке» и неактивна. Во время записи «Повторить» неактивны. Автоповтора нет. Список читается в фоне по всем `session.json` архива и обновляется при открытии меню, после обработки и после обслуживания архива: 400 записей за 0,1–0,16 с (NFR-07);
- «Показать последнюю запись в Finder», «Открыть папку записей», «Настройки…» (⌘,), «Проверить обновления…» (E5.2, FR-27: один запрос к GitHub по нажатию, неактивен во время записи и обработки; при найденной версии ниже пункт «Доступно обновление X.Y.Z»), «Выйти».

По завершении обработки приходит уведомление macOS «Готово: реплик N, собеседников M» с названием записи «Встреча дд.мм.гггг чч:мм», клик открывает `transcript.md` (выключается в настройках). При ошибке: «Расшифровка записи <название> не удалась. Повторить: меню, Записи без результата» (приходит всегда, отмена ошибкой не считается). За сутки до удаления исходного аудио записи без результата: «Аудио записи <название> будет удалено через сутки…», один раз на запись (в `session.json` пишется `deletionWarnedAt`). Разрешение на уведомления система спрашивает при первом запуске; после пересборки (подпись ad-hoc) его может понадобиться выдать заново: Системные настройки → Уведомления → AI Recorder. Значок в меню-баре показывает состояние: волна (ожидание), волна с красной точкой (запись, точка красная и на тёмном меню-баре), круг с паузой (пауза), мигающие полоски (идёт расшифровка или разметка), круг с «!» (обработка только что упала; значок держится до новой записи или нового запуска обработки и после перезапуска приложения не появляется: старые ошибки видны в списке «Записи без результата»; отмена ошибкой не считается). Запись важнее обработки, обработка важнее ошибки. Новую запись можно начать сразу, пока обрабатывается предыдущая (решение 42): в меню видно «Расшифровка, N%», «Обрабатывается запись <название>» и «В очереди записей: N». Остановленная запись ждёт своей очереди, обработка идёт по одной. При выходе из приложения очередь теряется: такие записи остаются в списке «Записи без результата», их можно повторить оттуда или `./build/transcribe-session --all`. Расшифровку можно отменить, и при следующем запуске она продолжится с готовых чанков.

При первом старте записи macOS спрашивает два разрешения:
1. Микрофон.
2. «Запись экрана и системного звука». После выдачи этого разрешения приложение нужно перезапустить.

Подпись ad-hoc: сертификата нет, и macOS привязывает разрешения к хешу подписи. По той же причине в entitlements включён `com.apple.security.cs.disable-library-validation`: иначе hardened runtime не загрузит ad-hoc подписанные `whisper.framework` и dylib sherpa-onnx (у приложения и библиотек нет общего Team ID). **После каждой пересборки `build-app.sh` разрешения может понадобиться выдать заново.** Если запись не стартует, откройте Системные настройки → Конфиденциальность и безопасность, удалите старую запись AI Recorder и включите новую.

Признак этой ситуации: в настройках переключатель AIRecorder включён, а меню пишет «Нет разрешения „Запись экрана и системного звука“». Переключатель относится к старой подписи: designated requirement у ad-hoc подписи равен хешу бинарника (`codesign -d -r- build/AIRecorder.app`), а он меняется при каждой сборке. Выключать и включать переключатель бесполезно, запись нужно сбросить:

```bash
osascript -e 'tell application id "com.neridov.airecorder" to quit'
tccutil reset ScreenCapture com.neridov.airecorder
open build/AIRecorder.app
```

Затем «Начать запись», разрешить в запросе macOS, выйти из приложения и открыть его снова. Если то же самое с микрофоном, сбросьте его так же: `tccutil reset Microphone com.neridov.airecorder`.

Запуск записи без клика по меню (для проверок): `open -n build/AIRecorder.app --args -autoRecordSeconds 90`. Приложение начнёт запись сразу и остановит её через 90 с. Флаг `-n` обязателен, если приложение уже запущено: без него `open` не передаст аргументы. Так же `--args -autoTranscribeLast YES` сразу расшифровывает последнюю запись, `--args -openSettings YES` открывает окно настроек.

Журнал: `log stream --predicate 'subsystem == "com.neridov.airecorder"' --info`.

## CI и выпуск версии

GitHub Actions (`.github/workflows/`):
- `ci.yml` — на каждый push в `main` и на pull request: `bash -n` для `install.sh` и `scripts/`, `fetch-sherpa-onnx.sh`, `swift test`, `build-app.sh` и проверка подписи `.app`. Раннер `macos-15` (Apple Silicon). Модели не скачиваются: тесты работают на заглушках.

1. Поднять `CFBundleShortVersionString` (например, `0.2.0`) и `CFBundleVersion` в `Resources/Info.plist`, закоммитить и запушить в `main`, дождаться зелёного CI.


3. Когда `Release` закончится, у коллег по «Проверить обновления…» появится «Доступна версия 0.2.0». Описание релиза можно поправить на GitHub.

## Что пишется

`~/Documents/AI Recorder/<Встреча дд.мм.гггг чч-мм>/` (E5.1, ADR-006 решение 17; например «Встреча 03.11.2026 10-32»; две записи в одну минуту — « (2)», « (3)»). Время в имени через дефис: двоеточие Finder показал бы как «/» (проверено 03.11.2026: папка `10:32` видна в Finder как «10/32»). Секунды и точное время — в `startedAt` в `session.json`. Папки до E5.1 называются `<YYYY-MM-DD_HH-mm-ss>` и не переименовываются (на них ссылаются ADR и `reviewed.md`). Порядок записей везде (меню, «последняя запись» в CLI, список, очередь, сроки) — по `startedAt`, а не по имени папки; папка без читаемого `session.json` — по дате создания. В меню, уведомлениях, `transcript.md` и выводе CLI запись называется «Встреча дд.мм.гггг чч:мм» (с двоеточием), для старых папок тоже по `startedAt`. Пути с пробелами в Terminal берите в кавычки: `./build/verify-session ~/Documents/AI\ Recorder/"Встреча 03.11.2026 10-32"`.

Состав папки:

| Файл | Содержимое |
|------|-----------|
| `system.caf` | системный звук, 48 кГц, стерео, Float32 PCM; после обработки сжимается в `system.m4a` (E5) |
| `mic.caf` | микрофон в родной частоте устройства (встроенный микрофон MacBook Pro M5: 48 кГц, моно), Float32 PCM; после обработки сжимается в `mic.m4a` (E5) |
| `system.m4a`, `mic.m4a` | сжатые дорожки (E5, ADR-005): HE-AAC 40 и 24 кбит/с, та же частота, каналы и длина в кадрах |
| `session.json` | метаданные, создаётся при старте и обновляется каждые 5 с |
| `mixed.m4a` | сведение обеих дорожек: создаёт обработка перед расшифровкой (если сведения ещё нет) или `mix-session` (E2), AAC 48 кГц стерео 128 кбит/с; после обработки перекодируется в HE-AAC 40 кбит/с (E5) |
| `transcript.json` | расшифровка и разметка (E3, E4), основной формат; создаёт обработка после «Стоп» или `transcribe-session` |
| `transcript.md` | читабельная расшифровка с блоком «Оценка» (FR-15), перезаписывается при каждой обработке; `diarize-session` его не трогает |
| `.transcription.lock` | pid процесса, который сейчас расшифровывает или размечает сессию; удаляется по окончании |
| `Labels.txt` | (необязательно) эталон говорящих из Audacity для сверки FR-05, кладёт пользователь |

Во время записи дорожки пишутся без сжатия: около 0,56 МБ/с, то есть примерно 1 ГБ за 30 минут. После обработки приложение сжимает их (E5, раздел «Сжатие и срок хранения»): час записи — около 27 МБ дорожек и 18 МБ `mixed.m4a`. Через 30 дней аудио удаляется, текст остаётся.

Основные поля `session.json` (`schemaVersion` 5; версии 1–4 из ранних записей читаются так же, в них нет части блоков ниже):
- `status`: `recording` → `completed`, после сбоя `recovered`, при ошибке старта `failed`.
- `startedAt`, `stoppedAt`: ISO 8601, точность 1 с. Точное время хранится в host time.
- `hostTimebase`: numer/denom для перевода тиков `mach_absolute_time` в наносекунды.
- `startOffsetMs`: сдвиг старта **mic − system** со знаком. Отрицательное значение значит, что микрофон стартовал раньше.
- `system` / `mic`:
  - `firstSampleHostTime` (тики и секунды);
  - `framesWritten`, `durationSeconds`;
  - `startLatencyMs`: время от нажатия «Старт» до первого сэмпла, по FR-01 не больше 2000;
  - `deviceName`;
  - `gaps`: разрывы больше 20 мс. Недостающее заполняется тишиной (`filledFrames`), чтобы номер кадра оставался привязан ко времени;
  - `anchors`: пары (host time, номер кадра) раз в 60 с, для замера дрейфа в E2.
- `errors`: ошибки записи, захвата и восстановления. Они не глушатся: каждая пишется в журнал и сюда.
- `alignment` (схема 2, пишет `mix-session`):
  - `mixFile`, `outputSampleRate`, `mixDurationSeconds`;
  - `originHostTime`: кадр 0 сведения, первый сэмпл дорожки, стартовавшей раньше;
  - `startOffsetMs`, `systemLeadMs`, `micLeadMs`: сдвиг старта и тишина, добавленная перед каждой дорожкой;
  - `clippedSamples`: сэмплы, ограниченные до ±1 при сложении;
  - `drift`: по каждой дорожке `ppm`, `measuredRate`, `anchorCount`, `spanSeconds`, `maxResidualMs`; между дорожками `relativePpm`, `driftMsAtEnd`, `driftMsPer70Min`.
- `segments` (схема 3): отрезки записи между паузами. У каждого `index`, `startHostTime` (нажатие «Начать» или «Продолжить»), `endHostTime` («Пауза» или «Стоп»), `system` и `mic` с `startFrame`/`endFrame` (кадры дорожки, конец не включается; `null`, если дорожка в отрезке не дала ни одного буфера). Запись без пауз = один отрезок.
- `transcription` (схема 3): `status` (`running`, `done`, `failed`), `progress` 0..1, `chunksDone`/`chunksTotal`, `startedAt`, `finishedAt`, `audioSeconds` (обе дорожки по времени дорожки без пауз), `micSpeechSeconds` (речь mic после VAD и порога), `processingSeconds` (при возобновлении складывается), `realtimeFactor`, `modelVersion`, `transcriptFile`, `error`.
- `multipleVoices` (схема 4): `true`, если включён флаг «Несколько голосов в комнате»; без флага поля нет.
- `diarization` (схема 4): `status` (`running`, `done`, `failed`), `progress`, `startedAt`, `finishedAt`, `audioSeconds` (размеченный звук), `processingSeconds`, `realtimeFactor`, `modelVersion` (модели и порог), `speakers` (собеседников с репликами), `micDiarized`, `error`.
- `compression` (схема 5, E5): `status` (`done`, `failed`), `finishedAt`, `processingSeconds`, `error`, `tracks[]` (`track`: `system`, `mic` или `mixed`; `originalFile`, `file`, `codec`, `bitRate`, `originalBytes`, `bytes`). После сжатия `system.file` и `mic.file` указывают на `.m4a`.
- `keepAudio` (схема 5, FR-13): `true` — аудио этой записи никогда не удаляется по сроку. Новые записи пишут `false`, старые получают поле при сжатии.
- `audioDeleted`, `audioDeletedAt` (схема 5, FR-11): аудио удалено по сроку хранения и когда.

## Восстановление после сбоя

Пока файл открыт, `AVAudioFile` хранит в заголовке CAF размер данных −1 («до конца файла»), а сами данные сразу уходят на диск. При запуске приложение находит сессии со статусом `recording`, чей процесс уже не жив, и для каждой:
- исправляет заголовок CAF по фактическому размеру и отрезает неполный последний кадр;
- пересчитывает кадры и длительности;
- ставит статус `recovered` и записывает в `errors` подробности.

Пропадает не больше нескольких миллисекунд звука в буферах на момент сбоя.

## verify-session

```bash
./build/verify-session                       # последняя сессия
./build/verify-session ~/Documents/AI\ Recorder/2026-10-28_16-51-58
```

Утилита открывает обе дорожки через `AVAudioFile`, сверяет кадры файла с `session.json` и проверяет заголовок CAF, ничего не меняя. Печатает:
- частоты, длительности, первый сэмпл и задержку старта;
- разрывы и сдвиг старта;
- остаток «разница длительностей + сдвиг старта», который около нуля, если потерь нет;
- ошибки из `session.json`.

Также печатается дрейф по anchors (как в `mix-session`, без записи в `session.json`) и сведения о `mixed.m4a`, если он есть.

Код выхода 0 означает `ИТОГ: OK`, 1 означает, что найдены проблемы.

## mix-session (E2)

```bash
./build/mix-session                          # последняя сессия
./build/mix-session ~/Documents/AI\ Recorder/2026-10-28_16-51-58
./build/mix-session --all                    # все сессии и сводная таблица
./build/mix-session --format caf --no-write  # mixed.caf без потерь, session.json не меняется
```

Что делает:
1. Читает `system.caf` и `mic.caf`, исходные файлы не меняет.
2. Ставит дорожки на общую шкалу по `firstSampleHostTime`: дорожка, стартовавшая позже, получает в начале тишину длиной |`startOffsetMs`|.
3. Если частота микрофона не 48 кГц, ресемплирует его (`AVAudioConverter`, максимальное качество).
4. Системный звук остаётся стерео, микрофон в моно добавляется в оба канала. Пишет `mixed.m4a` через временный файл, поэтому при ошибке старое сведение не портится.
5. Считает дрейф по anchors: фактическую частоту каждой дорожки (наклон «кадр от host time», МНК), отклонение в ppm и расхождение mic − system за запись и в пересчёте на 70 мин.
6. Пишет `alignment` в `session.json`, печатает отчёт и пишет его в журнал (категория `alignment`).

Сессии со статусом `recording` пропускаются: сначала завершите запись или запустите приложение для восстановления. Дрейф считается, если у дорожки есть хотя бы два anchors на промежутке от 10 с, то есть для записей от 60 с. Коррекции дрейфа нет: по ADR-003 она добавляется, только если дрейф на 70 мин окажется больше 100 мс.

Пример (90-секундная запись 2026-10-28_16-51-58):

```
сдвиг старта mic − system: -93.4 мс; компенсирован: тишина перед system 93.4 мс, перед mic 0.0 мс
сведение: mixed.m4a, 48000 Гц, стерео, 90.113 с
дрейф system: +0.00 ppm (48000.000 Гц при номинале 48000), anchors 2 на 60 с
дрейф mic: -3.76 ppm (47999.820 Гц при номинале 48000), anchors 2 на 60 с
дрейф mic − system: -3.76 ppm, -0.3 мс за 90 с записи, -15.8 мс на 70 мин
```

Ограничение: anchors системной дорожки идут ровно через 60,000000 с. Похоже, ScreenCaptureKit вычисляет PTS от числа кадров, и тогда замер показывает дрейф микрофона относительно часов хоста, а дрейф внутри ScreenCaptureKit не виден. Поэтому на длинной записи обязательна проверка на слух в конце.

## Пауза и возобновление (FR-14)

«Пауза» останавливает захват (индикатор микрофона в macOS гаснет), файлы дорожек остаются открытыми. «Продолжить запись» запускает захват заново, и первый буфер каждой дорожки дополняется тишиной на всю длину паузы, без предела в 300 с, как у обычных разрывов. Номер кадра остаётся привязан ко времени, поэтому `mix-session` и `verify-session` работают как раньше, а таймлайн сохраняет реальное время встречи. Пауза не попадает в `gaps`, её видно по `segments`. Расшифровка паузы пропускает.

Цена: тишина занимает место, около 1,4 ГБ за час паузы на обе дорожки без сжатия. «Остановить запись» на паузе завершает сессию, последний отрезок кончается моментом паузы.

## Расшифровка (E3)

```bash
./build/transcribe-session                       # последняя сессия
./build/transcribe-session ~/Documents/AI\ Recorder/2026-10-29_12-02-22
./build/transcribe-session --all                 # все завершённые без готовой расшифровки
./build/transcribe-session --restart             # заново, не продолжать с готовых чанков
./build/transcribe-session --system-whole        # system целиком, без VAD (для сравнения)
./build/transcribe-session --language auto       # определять язык (по умолчанию ru)
```

Приложение делает то же самое само после «Остановить запись» (или по «Повторить расшифровку» в списке «Записи без результата»). Что происходит (ADR-004, решения 11–22):
1. Сессия в статусе `recording` не расшифровывается. Если в `session.json` нет `alignment`, сначала выполняется сведение, как в `mix-session`.
2. Каждая дорожка читается в моно 16 кГц, исходные файлы не меняются.
3. Детектор речи Silero находит отрезки речи. На `mic` дополнительно действует порог громкости: отрезок остаётся, если он тише громкой речи дорожки не больше чем на 18 дБ, остальной звук обнуляется. Так фоновый шум AirPods не превращается в выдуманный текст. На `system` порога нет.
4. Дорожка делится на чанки по 5 минут (граница сдвигается в самое тихое место в ±5 с), паузы записи исключаются. Внутри чанка отрезки речи с паузами до 5 с собираются в окна до 30 с, каждое окно расшифровывает Whisper large-v3-turbo q5 на Metal. Порядок: все чанки `system`, затем `mic`.
5. После каждого чанка `transcript.json` перезаписывается атомарно, а `transcription` в `session.json` обновляется. После сбоя или отмены следующий запуск продолжает с первого неготового чанка, если не поменялись модель, язык и режим `system`.

`transcript.json` (схема 1): `sessionId`, `modelVersion`, `language`, `systemVAD`, `createdAt`, `updatedAt`, `chunks[]` (`track`, `index`, `startSample`, `endSample` в сэмплах 16 кГц от начала дорожки, `done`), `segments[]` и `speakers[]`. Реплика по модели ADR-004 (раздел 6): `id` (`<дорожка>-<чанк>-<номер>`), `sessionId`, `track`, `speakerId` (`me` для mic; `null` для system до разметки говорящих в E4), `startMs`, `endMs`, `text`, `language`, `confidence` (среднее геометрическое вероятностей токенов, 0..1), `overlapWith` (пусто до E4), `modelVersion`. Реплики отсортированы по `startMs`. Время считается в мс от `alignment.originHostTime`: время в дорожке плюс `systemLeadMs` или `micLeadMs`, то есть совпадает с таймлайном `mixed.m4a`.

Вывод на записи 2026-10-29_12-02-22 (10 мин, микрофон AirPods 24 кГц):

```
модель: whisper.cpp b5454 / large-v3-turbo-q5_0, загружена за 5.2 с
  готово: transcript.json, реплик 163 (system 119, mic 44)
  звук: 20.4 мин (system и mic по времени дорожки, без пауз)
  речь mic после VAD: 3.0 мин
  обработка: 28.7 с, 42.6× быстрее реального времени
  оценка NFR-02: час записи ≈ 2.8 мин обработки (норма ≤ 5 мин)
```

Оценка NFR-02 пересчитывает время обработки на час записи линейно. На двух 10-минутных записях выходит 2,7–3,2 мин на час (норма ≤ 5 мин), пик памяти около 1 ГБ. Точная проверка на 70-минутной записи ждёт B-01 в плане.

Сетевой трафик при расшифровке нулевой (NFR-01). Проверено `nettop`: процесс приложения и `transcribe-session` за всю расшифровку не открыли ни одного сокета. Повторить проверку:

```bash
nettop -P -L 0 -s 1 -x -J bytes_in,bytes_out | grep -i -E "AIRecorder|transcribe"
```

Пока идёт расшифровка, вывод должен оставаться пустым.

Журнал расшифровки: категория `transcription` в `log stream --predicate 'subsystem == "com.neridov.airecorder"' --info`.

## Разметка говорящих (E4)

```bash
./build/transcribe-session                       # расшифровка, затем разметка
./build/transcribe-session --no-diarize          # только расшифровка
./build/diarize-session                          # только разметка последней сессии (расшифровка должна быть готова)
./build/diarize-session ~/Documents/AI\ Recorder/2026-10-29_12-02-22
./build/diarize-session --all                    # все расшифрованные без разметки
./build/diarize-session --threshold 1.0          # другой порог кластеризации (больше — меньше собеседников)
./build/diarize-session --embedding nemo_en_titanet_small.onnx   # другая модель голоса из папки моделей
./build/diarize-session --multiple-voices on     # записать флаг «несколько голосов в комнате» и разметить mic тоже
```

После расшифровки сразу запускается разметка, затем пишется `transcript.md`. Что происходит (ADR-004, решения 23–32):
1. Нужна готовая расшифровка (все чанки `done`). Разметка каждый раз делается заново и не трогает текст реплик.
2. `system` читается в моно 16 кГц и целиком уходит в sherpa-onnx: сегментация pyannote-3.0 находит ходы говорящих, модель голоса 3D-Speaker CAM++ считает отпечаток каждого хода, ходы кластеризуются по порогу. Расчёт на CPU в 4 потока.
3. Каждая реплика `system` получает кластер, с которым пересекается дольше всего (без пересечения ближайший ход в пределах 2 с, иначе `speakerId = null`). Кластеры нумеруются по первой реплике: `speaker-1` «Собеседник 1» и дальше.
4. `mic` без флага целиком «Я» (`me`). С флагом «Несколько голосов в комнате» `mic` размечается так же, кластер с наибольшей речью остаётся «Я», остальные получают следующие номера собеседников. Кластеры разных дорожек не сопоставляются: один человек на `system` и на `mic` будет двумя говорящими.
5. Реплики разных говорящих, пересекающиеся не меньше чем на 250 мс, получают друг друга в `overlapWith` (перебивание).
6. `transcript.json` перезаписывается атомарно, в `session.json` пишется блок `diarization`.

Отмена в меню срабатывает между дорожками: внутри дорожки sherpa-onnx не прерывается. Если расшифровку запустить заново (`--restart` или сменился режим), разметка сбрасывается и делается после неё снова.

В `transcript.json` после разметки: у реплик `system` `speakerId` = `speaker-N`, `overlapWith` заполнен, `speakers[]` = `{id, sessionId, label, displayName: null}` для «Я» и каждого собеседника с репликами, блок `diarization` (`modelVersion`, `micDiarized`, `createdAt`). Переименование собеседника (позже, в интерфейсе) меняет только `displayName`.

**`transcript.md` (FR-15, решения 35 и 38).** В начале блок «Оценка»: поля `___` для вашей оценки (пригодность текста, сколько людей говорило, замечания) и то, что программа знает сама (средняя уверенность, реплики ниже 50% для проверки по звуку, собеседников по разметке, реплик по говорящим, перебиваний). Затем «Текст»: `**[мм:сс] Собеседник 2:** …`, время от начала `mixed.m4a`. Подряд идущие реплики одного говорящего с паузой до 3 с склеены в одну строку, перебивание помечено `_(перебивание: Я)_`. Свои правки сохраняйте в отдельный файл (например `reviewed.md`): `transcript.md` перезаписывается при повторной обработке.

**Сверка с эталоном (FR-05, критерий B, решения 33 и 40).** Если в папке сессии лежит `Labels.txt` (метки Audacity на `mixed.m4a`: начало, конец, имя; «я» или «Я» = вы), `diarize-session` и `transcribe-session` печатают критерий B: чистоту кластеров (каждому кластеру его самое частое имя, все метки вместе с «я», норма ≥ 85%, решение 41) и число кластеров на собеседника (не больше 5). Отдельно: «я» на «Я», собеседники после сопоставления (чистота без «я»), больше всего кластеров у одного человека, строгий показатель 1 к 1 (справка, не критерий).

Вывод на записи 2026-10-29_12-13-49 (`diarize-session`, эталон `Labels.txt`):

```

  реплик по говорящим: Я 45, Собеседник 1 54, Собеседник 2 20, Собеседник 3 8, Собеседник 4 2, Собеседник 5 1, Собеседник 6 11, Собеседник 7 6, Собеседник 8 1, Собеседник 9 1
```

## Сжатие и срок хранения (E5, E5.1)

Решения и замеры — в ADR-005 (сжатие) и ADR-006 (сроки, настройки, список записей без результата).

**Два вида аудио.** Исходное (сырое): `system.caf`, `mic.caf` и `mixed`, около 2 ГБ на час. Сжатое: `system.m4a`, `mic.m4a`, `mixed.m4a`, около 45 МБ на час.

**Что происходит само.** Приложение при запуске, раз в сутки и после каждой обработки проверяет архив, но только когда нет записи и обработки (R-03):
1. Запись с успешным результатом сжимается. Результат успешный, если расшифровка и разметка «готово», `transcript.json` и `transcript.md` есть и не пустые, реплик хотя бы одна. Сжатие: `system.caf` → `system.m4a`, `mic.caf` → `mic.m4a`, `mixed.m4a` перекодируется на месте. Сначала пишется временный `.<имя>.partial.m4a`, проверяется длина, затем `rename`, запись `session.json` и только потом удаление `.caf` (исходное аудио удаляется сразу после успешного сжатия). Если кодирование упало, исходники остаются, ошибка в `compression.error` и `errors`, сжатие повторится при следующей проверке. Новая запись или обработка прерывают сжатие без следа. Запись с пустым результатом не сжимается: исходное аудио остаётся для повтора.
2. Сжатое аудио удаляется через `compressedAudioRetentionDays` суток от окончания сжатия (`compression.finishedAt`), по умолчанию 7.
3. Исходное аудио записей без успешного результата (ошибка, отмена, не запускалась, восстановлена после сбоя, пустой результат) и записей, у которых не удалось сжатие, удаляется через `rawAudioRetentionDays` суток от начала записи (`startedAt`), по умолчанию 7. За сутки до этого приходит уведомление (кроме записей со сбоем сжатия: текст у них есть).
4. При удалении убираются только звуковые файлы и временные `.*.partial.*`. `transcript.json`, `transcript.md`, `session.json`, `Labels.txt`, `reviewed.md` остаются. В `session.json` пишутся `audioDeleted: true`, `audioDeletedAt`, `audioDeletedReason` (`retention` — сжатое, `rawExpired` — исходное), схема 6. В `transcript.md`, если он есть, первой строкой блока «Оценка» появляется «Аудио удалено (ДД.ММ.ГГГГ).»; если там уже есть отметка E5 «Аудио удалено по сроку хранения (…)», вторая не вставляется. Поля «Оценки», которые вы заполнили, не меняются.

Не удаляются никогда: запись, которая идёт; запись в очереди или в обработке; запись с «Не удалять аудио» (`keepAudio: true`); срок «не удалять»; записи, сделанные до перехода на E5.1.

**Переход на E5.1.** При первом запуске сборки E5.1 в настройки пишется `retentionPolicyStartedAt` (дата и время запуска). Записи с `startedAt` раньше этой даты автоматически не удаляются, обработанные из них по-прежнему сжимаются. Так защищены калибровочные записи FR-05 и записи с `reviewed.md`; старые записи удаляйте в Finder. Проверка:

```bash
defaults read com.neridov.airecorder retentionPolicyStartedAt
```

**Окно «Настройки…»** (меню, ⌘,). Изменения применяются сразу, кнопки «Сохранить» нет:
- «Хранение»: «Хранить сжатое аудио обработанных записей» и «Хранить исходное аудио записей без результата» — 1, 3, 7, 14, 30, 90 дней или «Не удалять». Если новый срок короче и сразу удалит аудио существующих записей, окно спросит «Будет удалено аудио N записей. Продолжить?»; «Отмена» возвращает прежнее значение. Новый срок проверяется сразу (если нет записи и обработки).
- «Обработка»: «Запускать обработку автоматически после «Стоп»» (выключено — запись попадает в «Записи без результата» с причиной «не запускалась»), «Язык расшифровки»: русский или «Определять автоматически».
- «Уведомления»: «Уведомление по завершении обработки». Уведомления об ошибке и о скором удалении приходят всегда.
- «Папка архива»: «Выбрать…», «По умолчанию» (`~/Documents/AI Recorder`). Применяется после перезапуска приложения, существующие записи не переносятся.

Порог разметки, модели, битрейты сжатия, `mergeGapMs`, `maxGapMs` в окно не вынесены: они откалиброваны под FR-05. Значения хранятся в `UserDefaults` домена `com.neridov.airecorder` (`compressedAudioRetentionDays`, `rawAudioRetentionDays`, `recordingsRoot`, `autoProcessOnStop`, `notifyOnDone`, `transcriptionLanguage`); значение вне списка читается как значение по умолчанию. Ключ E5 `retentionDays` больше не читается.

Окно сделано своим `NSWindow` (меню-бар без Dock): перед показом приложение активируется явно (`NSApp.activate`), окно выводится на передний план. У формы задан размер 560 × 600: без него окно сжималось до одной строки заголовка.

**Не удалять аудио записи (FR-13).** В меню: «Не удалять аудио этой записи» (текущая или последняя запись) или «Не удалять аудио» в подменю записи из списка «Записи без результата». Если запись в этот момент обрабатывается или идёт обслуживание архива, флаг запишется сразу после них. Вручную по-прежнему можно поставить `"keepAudio" : true` в `session.json`, когда запись не обрабатывается.

**Тестовые аргументы запуска** (на один запуск, в настройки не сохраняются): `-recordingsRoot <папка>` — другой архив, `-compressedAudioRetentionDays N`, `-rawAudioRetentionDays N` (N из списка 1, 3, 7, 14, 30, 90, -1), `-retentionPolicyStartedAt 2020-01-01T00:00:00Z` — дата перехода (иначе на копии старых записей ничего не удалится). Аргумент `-retentionDays` удалён. Пример проверки на копии:

```bash
open -n build/AIRecorder.app --args -recordingsRoot ~/Desktop/test-archive -retentionPolicyStartedAt 2020-01-01T00:00:00Z -compressedAudioRetentionDays 1 -rawAudioRetentionDays 1
```

Сжатые дорожки читают все CLI: `verify-session` печатает блок «Сжатие» и для записи с удалённым аудио только отметку с причиной. `transcribe-session` и `diarize-session` работают по сжатым дорожкам, но сами не сжимают (это делает приложение); `transcribe-session` при пустой расшифровке не запускает разметку. Расшифровка заново по сжатым дорожкам даёт немного другой текст, чем по исходным (ADR-005, «Измерения»), разметка — почти тот же результат.

Сеть при сжатии, удалении и уведомлениях не используется (NFR-01), проверка: команда `nettop` из раздела «Расшифровка (E3)», ищите `AIRecorder`.

## Чек-лист E2: сдвиг на 5 записях

Тесты RecorderCore не зависят от whisper и sherpa-onnx: движки подменяются заглушками. Реальные модели проверяются прогоном `transcribe-session` и `diarize-session` на записях.

Аудиопоток только копирует буфер, а запись в файл, счёт кадров и ошибки обрабатываются на последовательной очереди `TrackWriter`. PTS ScreenCaptureKit и `AVAudioTime.hostTime` микрофона идут в одних часах (`mach_absolute_time`) и сравниваются напрямую.

Сведение не меняет исходные дорожки. Кадр 0 сведения соответствует `alignment.originHostTime`, поэтому таймкоды расшифровки (E3) переводятся в host time без потерь.

Вне E1–E5.1: переподключение при смене устройства, коррекция дрейфа (только если понадобится по ADR-003), программный фильтр эха (ADR-004 решение 4), переименование собеседников и вид в две колонки (интерфейс, позже), SQLite, поиск и список встреч, ручное удаление аудио в приложении (FR-12; решения 02.11.2026, удаление вручную в Finder; исключение — «Удалить…» для записей без результата, ADR-006 решение 19), автоповтор расшифровки.
